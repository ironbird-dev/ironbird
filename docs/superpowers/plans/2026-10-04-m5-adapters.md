# M5 Adapters Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@ironbird/redux` (`fromStore`, `withIronbirdRestore`) and `@ironbird/xstate` (`fromActor` with an `actor()` accessor), two ESM and CommonJS packages that turn a Redux 5 store or an XState 5 root actor into a core `Target` with validated commands, projected state, `persist`, and schema-checked `restore`. Each package gets an in-repo headless sample that `@ironbird/testing`'s `modelTest` drives, plus the api.md Adapters section and changesets.

**Architecture:** Both adapters are thin wrappers over core's `createTarget`, so the registry validates every payload before the adapter's mapping sees it (rule 4). `fromStore` subscribes to the store, notifies only when the root state reference changes, persists `store.getState()`, and restores by parsing the snapshot with the app's Zod schema and then dispatching one internal action that the `withIronbirdRestore` reducer wrapper answers. If the state afterwards isn't the parsed value, the reducer wasn't wrapped and the load fails `INVALID_SNAPSHOT`. `fromActor` owns the target's listener set and its single subscription to the live actor. Restore parses with `snapshotSchema`, builds and starts the replacement with an error observer attached before `start()`, and only then moves the subscription, swaps the live actor, stops the old one, and notifies once (spec §3).

**Tech Stack:** TypeScript 6 strict, tsup 8 (ESM + CJS + d.ts, `platform: 'neutral'`), Redux 5.0.1 and Redux Toolkit 2.13.0 (tests), XState 5.33.2, Zod 4.6 (peer `^4.2.0`), Vitest 5 `unit` project, `@ironbird/testing` `modelTest` and `createTestTarget`, ESLint flat config with `@typescript-eslint/no-restricted-imports`, Changesets.

**Spec:** [docs/superpowers/specs/2026-10-04-m5-adapters-and-0.1-design.md](../specs/2026-10-04-m5-adapters-and-0.1-design.md). This plan implements D1, D2, D3, §3, the "Adapters" rows of §11, and §7's api.md Adapters bullet. The cross-plan names come from `.superpowers/sdd/m5-contract.md` (not committed), "Plan 1: adapters". Plan 2 (snapshots and watch) runs **before** this plan and supplies `INVALID_SNAPSHOT`, `createTarget`'s restore-error conversion, and the headless `snapshotSave`/`snapshotLoad`. Plan 4 consumes `@ironbird/redux`.

| Restore and invoked actors | Restoring a state that invokes a `fromCallback` actor runs the callback again (starts 1 → 2), and stopping the old actor runs its cleanup (stops 0 → 1). Context7 (Stately docs, "Persistence"): "Actions from machine actors will not be re-executed, but invocations will be restarted" |
| Restore and delayed transitions | The persisted snapshot holds no scheduled events. A restored actor in a state with `after: { 100: ... }` schedules no timer, and the transition never fires. Stopping the old actor cancels its timer through `clock.clearTimeout` |
| Snapshots that fail to start | `_initState` catches a throwing `restoreSnapshot`, and `start()` then puts the actor in status `error`. `value: 'nowhere'` gives `State 'nowhere' does not exist on 'counter'`, and a snapshot without `children` gives `Cannot convert undefined or null to object` (V8). `createActor` itself does not throw for these |
| Unhandled actor errors | `reportUnhandledError(err)` is `setTimeout(() => { throw err })`. `_reportError` calls it when the actor has no observers, **or when any observer lacks an `error` callback** (`reportError ||= !errorListener`). An observer with an `error` callback, subscribed before `start()`, captures a failed start without it |
| `stop()` | Sets the snapshot status to `stopped`, calls every observer's `complete`, and clears the observers. It throws `A non-root actor cannot be stopped directly.` for a child actor. Sending to a stopped actor is a silent no-op. Subscribing to a stopped actor is allowed and inert |
| Observer notifications | XState calls `next` for every processed event, even one no state handles, but the snapshot object is **the same reference** when nothing changed. An action that throws during a transition sets status `error` and calls `error` observers. An unstarted actor's snapshot status is `active` |
| `clock` option | Typed `{ setTimeout(fn: (...args: any[]) => void, timeout: number): any; clearTimeout(id: any): void }`. Core's `ManualClock` is assignable. The root actor's system scheduler uses it for `after` delays, and `clock.advance` fires them |

## Global Constraints

Copied from [AGENTS.md](../../../AGENTS.md) hard rules:

1. `@ironbird/core` imports only `zod`. No `react-native`, no `node:*` modules, no DOM or browser globals. It must run unmodified in Node and Hermes. Lint enforces this.
2. No arbitrary code execution anywhere. No `eval`, no `new Function`, and no protocol operation that runs caller-supplied code. Agents act only through declared commands and fake controls ([ADR-0001](../../adr/0001-commands-only-agent-surface.md)).
3. The bridge stays dev-only. The bridge marker constant is defined in `@ironbird/react-native` and nowhere else; the string must not appear in any other package.
4. Validate every payload where it is applied, including inside the app. Never trust the daemon.
5. Protocol changes update [docs/protocol.md](../../protocol.md) in the same PR. Breaking changes bump `PROTOCOL_VERSION` and need an ADR.
6. Public API or CLI changes update [docs/api.md](../../api.md) or [docs/cli.md](../../cli.md) in the same PR and include a changeset.
7. New runtime dependencies in `core` or `react-native` need an ADR. New dependencies in `cli` need a one-line justification in the PR.
8. Errors that cross a package boundary are `IronbirdError` with a code from the protocol error table. No bare string throws.
9. Headless determinism is a feature. Library code and example app logic take time from the injected `Clock`, never from global `setTimeout`, `setInterval`, or `Date.now`.

From the spec and the contract:

- `fromStore(store, { commands, toAction?, select?, restore? })` returns a core `Target`. `select` shapes only `getState`, `waitFor`, and `watch`. `persist` always returns the **root** state, `store.getState()`. `restore` exists only with `restore: { schema }`, and requires the root reducer to be wrapped with the exported `withIronbirdRestore(reducer)`. It validates with `schema` first, then dispatches one internal action carrying the parsed value. If the store's state afterwards isn't that value, it fails `INVALID_SNAPSHOT` (D1).
- `fromActor(actor, { commands, toEvent?, select?, restore? })` returns a `Target` plus `actor()`. `persist` uses `actor().getPersistedSnapshot()`. `restore` exists only with `restore: { snapshotSchema, actorOptions? }` (D2). The restore steps follow §3 exactly, with one deviation listed in the spec-discrepancies table: the live actor is swapped before the old one is stopped.
- At runtime the adapters import only `@ironbird/core` and, for `@ironbird/xstate`, `createActor` from `xstate`; everything else is a type import (D3). Peers: `@ironbird/core` `>=0.0.3`, `zod` `^4.2.0`, plus `redux` `^5.0.0` or `xstate` `^5.0.0`.
- `INVALID_SNAPSHOT` details are `{ path, reason }` (D12). `path` is the protocol's dot-separated path (`''` for the whole value), and `reason` is the Zod issue's message, or `actor failed to start: <message>` (§3 step 2).
- Package metadata: version `0.0.0` (the changeset makes it 0.0.1; plan 5's minor changeset makes it 0.1.0), MIT, `"type": "module"`, `sideEffects: false`, ESM and CommonJS builds with declarations, `files: ["dist"]`, and no `engines` (the adapters run in Hermes, like core).
- Named exports only. Tests live next to code as `*.test.ts`; fixtures and samples live in each package's `test/`. Durations are milliseconds.
- Packages import each other from `dist`. After changing core, run `pnpm --filter @ironbird/core build`. Adapter tests import `@ironbird/core` and `@ironbird/testing` from `dist`. `pnpm build` builds every package in dependency order.
- Commit messages are plain imperative subjects with no attribution trailers. Never commit `.superpowers/` or anything from the scratchpad.
- Run `pnpm test` under Node 22 as well as the local Node before pushing; CI runs both 22 and 26.
- Use this dependency justification in the PR, verbatim: "`@ironbird/redux` and `@ironbird/xstate` are new packages whose only runtime import is `@ironbird/core` (plus `createActor` from the `xstate` peer); `@ironbird/core`, `zod` ^4.2, and `redux` ^5 or `xstate` ^5 are peers, so apps keep their own versions (M5 design D3). Dev dependencies: `@reduxjs/toolkit` ^2.13 and `xstate` ^5.33 so the tests run against real stores and actors, and `@ironbird/testing` for the modelTest samples."

## Review Focus

These are the inputs the spec implies but no spec test names that are most likely to bite a user first. Each has a test in the task that owns the code.

1. **An event whose action throws.** The actor goes to status `error`. Through the adapter, this must not become an uncaught exception from XState's timer, whatever observers the app has. The dispatch fails `DISPATCH_FAILED` naming the error, the revision moves, and later dispatches say the actor is in error (Task 4, "fails DISPATCH_FAILED with the error when an event makes the actor fail, without an uncaught exception").
2. **A command payload with a key named `type`, or a payload that isn't an object.** The default event mapping must never let a payload rename the event, and it must not spread a string or number into index keys (Task 4, "never lets a payload key named type rename the event" and "sends a payload that is not an object as { type, payload }").
3. **A `toAction` that returns the internal restore action.** A command would then replace the whole state without the snapshot schema. It must fail `DISPATCH_FAILED` and leave the store untouched (Task 1, "refuses a command that maps to the restore action").
4. **A `snapshotSchema` written with `z.object`, which strips the `children` and `historyValue` XState needs.** The load must fail `INVALID_SNAPSHOT` with `actor failed to start: ...` and keep the old actor live; api.md tells apps to use `z.looseObject` (Task 5, "when the schema strips the children XState needs").
5. **A snapshot saved while an `after` transition was pending.** XState doesn't persist scheduled events, so the restored actor waits forever. This is recorded by a test and documented, rather than surprising the user (Task 5, "does not reschedule a delayed transition").

```js
import { createRequire } from 'node:module';
import { readFileSync, readdirSync } from 'node:fs';
import { join } from 'node:path';

const dist = new URL('../dist/', import.meta.url);
const require = createRequire(import.meta.url);
const expected = ['fromStore', 'withIronbirdRestore'];
const allowed = new Set(['@ironbird/core']);

const builds = [['cjs', require('../dist/index.cjs')], ['esm', await import('../dist/index.js')]];
for (const [format, mod] of builds) {
  const names = Object.keys(mod).sort();
  if (JSON.stringify(names) !== JSON.stringify(expected)) throw new Error(`the ${format} build exports ${names.join(', ')}; expected ${expected.join(', ')}`);
  for (const name of names) {
    if (typeof mod[name] !== 'function') throw new Error(`${name} is not a function in the ${format} build`);
  }
}

for (const file of readdirSync(dist)) {
  if (!file.endsWith('.js') && !file.endsWith('.cjs')) continue;
  const source = readFileSync(join(dist.pathname, file), 'utf8');
  for (const match of source.matchAll(/(?:from\s+|require\()["']([^"']+)["']/g)) {
    const specifier = match[1];
    if (specifier.startsWith('.')) continue;
    if (!allowed.has(specifier)) throw new Error(`${file} imports ${specifier}; @ironbird/redux may import only @ironbird/core at runtime (M5 design D3)`);
  }
  if (source.includes('__IRONBIRD_BRIDGE')) throw new Error(`${file} contains the bridge marker; it must live only in @ironbird/react-native`);
}
console.log(`@ironbird/redux build verified: esm and cjs export ${expected.join(', ')}; runtime imports only @ironbird/core`);
```

```ts
import type { Action, Reducer } from 'redux';

/** The one action `withIronbirdRestore` answers. Only `fromStore`'s `restore` dispatches it. */
export const RESTORE_ACTION_TYPE = '@@ironbird/restore';

export interface RestoreAction extends Action<typeof RESTORE_ACTION_TYPE> {
  payload: unknown;
}

export function isRestoreAction(action: unknown): action is RestoreAction {
  return typeof action === 'object' && action !== null && (action as { type?: unknown }).type === RESTORE_ACTION_TYPE;
}

/**
 * Wraps the app's root reducer so `fromStore`'s `restore` can replace the whole state (M5 design
 * D1). The restore action carries a value `fromStore` already parsed with the app's schema, so the
 * reducer never receives an unvalidated snapshot (AGENTS.md rule 4). Every other action goes to
 * `reducer` unchanged.
 */
export function withIronbirdRestore<S, A extends Action, P = S>(reducer: Reducer<S, A, P>): Reducer<S, A, P> {
  return (state, action) => (isRestoreAction(action) ? (action.payload as S) : reducer(state, action));
}
```

```ts
import { createTarget, type CommandOf, type CommandRegistry, type Target } from '@ironbird/core';
import type { Action, Store, UnknownAction } from 'redux';
import { RESTORE_ACTION_TYPE, isRestoreAction } from './restore';

export interface FromStoreOptions<R extends CommandRegistry, S, A extends Action = UnknownAction> {
  commands: R;
  /** Maps a validated command to an action. Default: `{ type: name, payload }`, the shape Redux Toolkit's action creators produce. */
  toAction?: (command: CommandOf<R>) => A;
  /** Shapes the state that `getState`, `waitFor`, and `watch` see. Default: the whole state. `persist` ignores it. */
  select?: (state: S) => unknown;
}

/**
 * A core `Target` over a Redux store (M5 design D1). Commands are validated by the registry before
 * `toAction` sees them. `persist` saves the root state, never the projection.
 */
export function fromStore<R extends CommandRegistry, S, A extends Action = UnknownAction>(store: Store<S, A>, options: FromStoreOptions<R, S, A>): Target {
  const toAction = options.toAction ?? ((command: CommandOf<R>): A => ({ type: command.name, payload: command.payload }) as unknown as A);
  const select = options.select ?? ((state: S): unknown => state);
  return createTarget({
    commands: options.commands,
    dispatch(command) {
      const action = toAction(command);
      // Only a schema-checked snapshot may replace the state; a command never bypasses the schema.
      if (isRestoreAction(action)) throw new Error(`${command.name} maps to ${RESTORE_ACTION_TYPE}, which only snapshotLoad may dispatch`);
      store.dispatch(action);
    },
    getState: () => select(store.getState()),
    // Redux notifies after every dispatch, even one no reducer handled. Comparing the root state by
    // reference moves the target's revision only when the state changed.
    subscribe(listener) {
      let last = store.getState();
      return store.subscribe(() => {
        const next = store.getState();
        if (next === last) return;
        last = next;
        listener();
      });
    },
    persist: () => store.getState(),
  });
}
```

```ts
/** The part of a Zod issue the error needs; Zod 4's `$ZodIssue` satisfies it. */
export interface SchemaIssue {
  readonly path: ReadonlyArray<PropertyKey>;
  readonly message: string;
}

/**
 * `INVALID_SNAPSHOT` for the first issue the app's schema reported (M5 design D12), with the
 * protocol's dot-separated path (`''` for the whole state) and the issue's message as `reason`.
 */
export function invalidSnapshot(issues: readonly SchemaIssue[]): IronbirdError {
  const first = issues[0];
  const path = first ? first.path.map(String).join('.') : '';
  const reason = first ? first.message : 'the snapshot does not match the schema';
  return new IronbirdError('INVALID_SNAPSHOT', `Invalid snapshot${path === '' ? '' : ` at ${path}`}: ${reason}`, { path, reason });
}
```

```ts
import { IronbirdError, createTarget, type CommandOf, type CommandRegistry, type Target } from '@ironbird/core';
import type { Action, Store, UnknownAction } from 'redux';
import type { z } from 'zod';
import { invalidSnapshot } from './errors';
import { RESTORE_ACTION_TYPE, isRestoreAction } from './restore';

export interface FromStoreOptions<R extends CommandRegistry, S, A extends Action = UnknownAction> {
  commands: R;
  /** Maps a validated command to an action. Default: `{ type: name, payload }`, the shape Redux Toolkit's action creators produce. */
  toAction?: (command: CommandOf<R>) => A;
  /** Shapes the state that `getState`, `waitFor`, and `watch` see. Default: the whole state. `persist` ignores it. */
  select?: (state: S) => unknown;
  /** Enables `restore`. Pass it only when the store's root reducer is wrapped with `withIronbirdRestore`. */
  restore?: { schema: z.ZodType<S> };
}

/**
 * A core `Target` over a Redux store (M5 design D1). Commands are validated by the registry before
 * `toAction` sees them. `persist` saves the root state, never the projection; `restore` exists only
 * with `options.restore`.
 */
export function fromStore<R extends CommandRegistry, S, A extends Action = UnknownAction>(store: Store<S, A>, options: FromStoreOptions<R, S, A>): Target {
  const toAction = options.toAction ?? ((command: CommandOf<R>): A => ({ type: command.name, payload: command.payload }) as unknown as A);
  const select = options.select ?? ((state: S): unknown => state);
  const restoreOptions = options.restore;
  return createTarget({
    commands: options.commands,
    dispatch(command) {
      const action = toAction(command);
      // Only a schema-checked snapshot may replace the state; a command never bypasses the schema.
      if (isRestoreAction(action)) throw new Error(`${command.name} maps to ${RESTORE_ACTION_TYPE}, which only snapshotLoad may dispatch`);
      store.dispatch(action);
    },
    getState: () => select(store.getState()),
    // Redux notifies after every dispatch, even one no reducer handled. Comparing the root state by
    // reference moves the target's revision only when the state changed.
    subscribe(listener) {
      let last = store.getState();
      return store.subscribe(() => {
        const next = store.getState();
        if (next === last) return;
        last = next;
        listener();
      });
    },
    persist: () => store.getState(),
    ...(restoreOptions ? { restore: (snapshot: unknown) => restoreStore(store, restoreOptions.schema, snapshot) } : {}),
  });
}

function restoreStore<S, A extends Action>(store: Store<S, A>, schema: z.ZodType<S>, snapshot: unknown): void {
  const result = schema.safeParse(snapshot);
  if (!result.success) throw invalidSnapshot(result.error.issues);
  store.dispatch({ type: RESTORE_ACTION_TYPE, payload: result.data } as unknown as A);
  // A store whose root reducer isn't wrapped ignores the action, and the adapter can't tell from
  // the store instance, so it checks the outcome.
  if (store.getState() !== result.data) {
    throw new IronbirdError('INVALID_SNAPSHOT', 'The store ignored the snapshot: wrap the root reducer with withIronbirdRestore', {
      path: '',
      reason: 'the root reducer is not wrapped with withIronbirdRestore',
    });
  }
}
```

```ts
import { defineCommands, defineHeadless } from '@ironbird/core';
import { combineReducers, configureStore, createSlice, type PayloadAction } from '@reduxjs/toolkit';
import { z } from 'zod';
import { fromStore, withIronbirdRestore } from '../src/index';

// The in-repo sample for @ironbird/redux (M5 design §10, plan 1): a to-do list capped at three
// items, in a Redux Toolkit store whose root reducer is wrapped for restore. With
// `env.BUG === '1'`, `todos/add` skips the cap, the planted bug the model test must find. The
// target shows only `state.todos`; snapshots carry the root state, `meta` included.

export const MAX_TODOS = 3;

export interface Todo {
  text: string;
  done: boolean;
}

export interface TodosState {
  items: Todo[];
}

const todosSlice = (buggy: boolean) =>
  createSlice({
    name: 'todos',
    initialState: { items: [] } as TodosState,
    reducers: {
      add(state, action: PayloadAction<{ text: string }>) {
        if (!buggy && state.items.length >= MAX_TODOS) return;
        state.items.push({ text: action.payload.text, done: false });
      },
      toggle(state, action: PayloadAction<{ index: number }>) {
        const item = state.items[action.payload.index];
        if (item) item.done = !item.done;
      },
      clearDone(state) {
        state.items = state.items.filter((item) => !item.done);
      },
    },
  });

export function createTodoStore(buggy = false) {
  const rootReducer = combineReducers({
    todos: todosSlice(buggy).reducer,
    meta: (state: { version: number } = { version: 1 }) => state,
  });
  return configureStore({ reducer: withIronbirdRestore(rootReducer) });
}

// Command names are the slice's action types, so the default `toAction` needs no mapping.
export const todoCommands = defineCommands({
  'todos/add': z.object({ text: z.string().min(1).max(20) }).describe('Add a to-do; the list holds at most three'),
  'todos/toggle': z.object({ index: z.number().int().min(0).max(4) }).describe('Toggle the to-do at index; an index past the end does nothing'),
  'todos/clearDone': z.object({}).describe('Remove every finished to-do'),
});

export const todoStateSchema = z.object({
  todos: z.object({ items: z.array(z.object({ text: z.string().min(1).max(20), done: z.boolean() })) }),
  meta: z.object({ version: z.number().int() }),
});

export const todoApp = defineHeadless(({ env }) => {
  const store = createTodoStore(env['BUG'] === '1');
  return {
    target: fromStore(store, { commands: todoCommands, select: (state) => state.todos, restore: { schema: todoStateSchema } }),
  };
});
```

```js
for (const [format, mod] of builds) {

  if (JSON.stringify(names) !== JSON.stringify(expected)) throw new Error(`the ${format} build exports ${names.join(', ')}; expected ${expected.join(', ')}`);
  for (const name of names) {
    if (typeof mod[name] !== 'function') throw new Error(`${name} is not a function in the ${format} build`);
  }
}

for (const file of readdirSync(dist)) {
  if (!file.endsWith('.js') && !file.endsWith('.cjs')) continue;
  const source = readFileSync(join(dist.pathname, file), 'utf8');
  for (const match of source.matchAll(/(?:from\s+|require\()["']([^"']+)["']/g)) {
    const specifier = match[1];

    if (!allowed.has(specifier)) throw new Error(`${file} imports ${specifier}; @ironbird/xstate may import only @ironbird/core and xstate at runtime (M5 design D3)`);

}
```

```ts
import { defineCommands } from '@ironbird/core';
import { assign, fromCallback, setup } from 'xstate';
import { z } from 'zod';

// A test fixture, never exported from the package: a counter with a note, a `busy` state that
// invokes a callback actor (whose starts and stops `lifecycle` counts), an action that throws, and
// an event no state handles.

export interface Lifecycle {
  started: number;
  stopped: number;
}

export interface CounterContext {
  count: number;
  note: string;
}

export function counterMachine(lifecycle: Lifecycle = { started: 0, stopped: 0 }) {
  const ticker = fromCallback(() => {
    lifecycle.started += 1;
    return () => {
      lifecycle.stopped += 1;
    };
  });
  return setup({
    types: {
      context: {} as CounterContext,
      events: {} as
        | { type: 'count.add'; by: number }
        | { type: 'note.set'; text: string }
        | { type: 'raw'; payload: unknown }
        | { type: 'busy.start' }
        | { type: 'busy.stop' }
        | { type: 'boom' }
        | { type: 'noop' },
    },
    actors: { ticker },
  }).createMachine({
    id: 'counter',
    initial: 'idle',
    context: { count: 0, note: '' },
    on: {
      'count.add': { actions: assign({ count: ({ context, event }) => context.count + event.by }) },
      'note.set': { actions: assign({ note: ({ event }) => event.text }) },
      raw: { actions: assign({ note: ({ event }) => JSON.stringify(event.payload) }) },
      boom: {
        actions: () => {
          throw new Error('boom');
        },
      },
    },
    states: {
      idle: { on: { 'busy.start': 'busy' } },
      busy: { invoke: { id: 'ticker', src: 'ticker' }, on: { 'busy.stop': 'idle' } },
    },
  });
}

export const counterCommands = defineCommands({
  'count.add': z.object({ by: z.number().int().min(1) }).describe('Add by'),
  // Declares a `type` key on purpose: the default event mapping must not let it rename the event.
  'note.set': z.object({ text: z.string(), type: z.string().optional() }).describe('Set the note'),
  raw: z.number().describe('A payload that is not an object'),
  'busy.start': z.object({}).describe('Enter busy, which invokes the ticker'),
  'busy.stop': z.object({}).describe('Leave busy'),
  boom: z.object({}).describe('Run an action that throws'),
  noop: z.object({}).describe('An event no state handles'),
});

/** Loose, so `children` and `historyValue` survive parsing; XState needs them to restore. */
```

Create `packages/xstate/src/from-actor.ts`:

```ts
import { createTarget, messageOf, type CommandOf, type CommandRegistry, type Target } from '@ironbird/core';
import type { Actor, AnyStateMachine, EventFromLogic, SnapshotFrom } from 'xstate';

export interface FromActorOptions<R extends CommandRegistry, TLogic extends AnyStateMachine> {
  commands: R;
  /** Maps a validated command to an event. Default: the payload's keys plus `type: name`; a payload that isn't an object becomes `{ type: name, payload }`. */
  toEvent?: (command: CommandOf<R>) => EventFromLogic<TLogic>;
  /** Shapes the state that `getState`, `waitFor`, and `watch` see. Default: `{ value, context }`. `persist` ignores it. */
  select?: (snapshot: SnapshotFrom<TLogic>) => unknown;
}

/** A core `Target` plus the live actor. */
export type ActorTarget<TLogic extends AnyStateMachine> = Target & {
  /** The live actor. A restore stops the old one, so read this again whenever the target notifies. */
  actor(): Actor<TLogic>;
};

const isRecord = (value: unknown): value is Record<string, unknown> => typeof value === 'object' && value !== null && !Array.isArray(value);

/** Spread first, `type` last: a payload key named `type` can't turn one command into another event. */
const defaultEvent = (command: { name: string; payload: unknown }): { type: string } & Record<string, unknown> =>
  isRecord(command.payload) ? { ...command.payload, type: command.name } : { type: command.name, payload: command.payload };

const defaultSelect = (snapshot: unknown): unknown => {
  const { value, context } = snapshot as { value: unknown; context: unknown };
  return { value, context };
};

/**
 * A core `Target` over a started XState v5 root actor (M5 design D2). The adapter owns its one
 * subscription to the actor and hands `createTarget` its own listener set.
 */
export function fromActor<R extends CommandRegistry, TLogic extends AnyStateMachine>(actor: Actor<TLogic>, options: FromActorOptions<R, TLogic>): ActorTarget<TLogic> {
  const current = actor;
  let last: unknown = current.getSnapshot();
  const listeners = new Set<() => void>();
  const notify = (): void => {
    for (const listener of listeners) listener();
  };
  // XState notifies observers for every event it processes, even one that changed nothing, and
  // keeps the snapshot object when nothing changed, so comparing references keeps the revision
  // honest. The error callback matters: XState rethrows an actor's error from a timer whenever any
  // observer lacks one, so a next-only observer here would turn every actor error into an uncaught
  // exception, even in an app that handles it. The target treats the error as a state change, and
  // the next dispatch fails with it.
  const changed = (): void => {
    const next = current.getSnapshot();
    if (next === last) return;
    last = next;
    notify();
  };
  current.subscribe({ next: changed, error: changed });

  const toEvent = options.toEvent ?? ((command: CommandOf<R>) => defaultEvent(command) as EventFromLogic<TLogic>);
  const select = options.select ?? defaultSelect;

  const target = createTarget({
    commands: options.commands,
    dispatch(command) {
      const { status } = current.getSnapshot() as { status: string };
      if (status !== 'active') throw new Error(`the actor is ${status}`);
      current.send(toEvent(command));
      const after = current.getSnapshot() as { status: string; error?: unknown };
      if (after.status === 'error') throw new Error(`the actor failed: ${messageOf(after.error)}`);
    },
    getState: () => select(current.getSnapshot()),
    subscribe(listener) {
      listeners.add(listener);
      return () => {
        listeners.delete(listener);
      };
    },
    persist: () => current.getPersistedSnapshot(),
  });
  return Object.assign(target, { actor: () => current });
}
```

```ts
import { IronbirdError, createTarget, messageOf, type CommandOf, type CommandRegistry, type Target } from '@ironbird/core';
import { createActor, type Actor, type ActorOptions, type AnyActorLogic, type AnyStateMachine, type EventFromLogic, type SnapshotFrom, type Subscription } from 'xstate';
import type { z } from 'zod';
import { invalidSnapshot } from './errors';

export interface FromActorOptions<R extends CommandRegistry, TLogic extends AnyStateMachine> {
  commands: R;
  /** Maps a validated command to an event. Default: the payload's keys plus `type: name`; a payload that isn't an object becomes `{ type: name, payload }`. */
  toEvent?: (command: CommandOf<R>) => EventFromLogic<TLogic>;
  /** Shapes the state that `getState`, `waitFor`, and `watch` see. Default: `{ value, context }`. `persist` ignores it. */
  select?: (snapshot: SnapshotFrom<TLogic>) => unknown;
  /**
   * Enables `restore` (M5 design §3). `snapshotSchema` validates a persisted snapshot before any
   * actor sees it; `actorOptions` (a clock, an inspector, an id) are passed to the replacement actor.
   */
  restore?: {
    snapshotSchema: z.ZodType;
    actorOptions?: Omit<ActorOptions<TLogic>, 'snapshot' | 'state'>;
  };
}

/** A core `Target` plus the live actor, which a restore replaces. */
export type ActorTarget<TLogic extends AnyStateMachine> = Target & {
  /** The live actor. A restore stops the old one, so read this again whenever the target notifies. */
  actor(): Actor<TLogic>;
};

const isRecord = (value: unknown): value is Record<string, unknown> => typeof value === 'object' && value !== null && !Array.isArray(value);

/** Spread first, `type` last: a payload key named `type` can't turn one command into another event. */
const defaultEvent = (command: { name: string; payload: unknown }): { type: string } & Record<string, unknown> =>
  isRecord(command.payload) ? { ...command.payload, type: command.name } : { type: command.name, payload: command.payload };

const defaultSelect = (snapshot: unknown): unknown => {
  const { value, context } = snapshot as { value: unknown; context: unknown };
  return { value, context };
};

/**
 * A core `Target` over a started XState v5 root actor (M5 design D2). The adapter owns its one
 * subscription to the live actor and hands `createTarget` its own listener set, so a restore can
 * swap actors without leaving the target on a stopped one.
 */
export function fromActor<R extends CommandRegistry, TLogic extends AnyStateMachine>(actor: Actor<TLogic>, options: FromActorOptions<R, TLogic>): ActorTarget<TLogic> {
  let current = actor;
  let last: unknown = current.getSnapshot();
  const listeners = new Set<() => void>();
  const notify = (): void => {
    for (const listener of listeners) listener();
  };
  // XState notifies observers for every event it processes, even one that changed nothing, and
  // keeps the snapshot object when nothing changed, so comparing references keeps the revision
  // honest. The error callback matters: XState rethrows an actor's error from a timer whenever any
  // observer lacks one, so a next-only observer here would turn every actor error into an uncaught
  // exception, even in an app that handles it. The target treats the error as a state change, and
  // the next dispatch fails with it.
  const changed = (): void => {
    const next = current.getSnapshot();
    if (next === last) return;
    last = next;
    notify();
  };
  const observe = (subject: Actor<TLogic>): Subscription => subject.subscribe({ next: changed, error: changed });
  let subscription = observe(current);

  const toEvent = options.toEvent ?? ((command: CommandOf<R>) => defaultEvent(command) as EventFromLogic<TLogic>);
  const select = options.select ?? defaultSelect;
  const restoreOptions = options.restore;

  const restore = (snapshot: unknown): void => {
    if (!restoreOptions) return;
    const parsed = restoreOptions.snapshotSchema.safeParse(snapshot);
    if (!parsed.success) throw invalidSnapshot(parsed.error.issues);
    const replacement = startReplacement(current.logic, { ...restoreOptions.actorOptions, snapshot: parsed.data } as ActorOptions<TLogic>);
    // Only now is the live actor touched. Swapping before stopping means an app observer that
    // reacts to the old actor completing already reads the replacement through `actor()`.
    subscription.unsubscribe();
    subscription = observe(replacement);
    const previous = current;
    current = replacement;
    last = replacement.getSnapshot();
    previous.stop();
    notify();
  };

  const target = createTarget({
    commands: options.commands,
    dispatch(command) {
      const { status } = current.getSnapshot() as { status: string };
      if (status !== 'active') throw new Error(`the actor is ${status}`);
      current.send(toEvent(command));
      const after = current.getSnapshot() as { status: string; error?: unknown };
      if (after.status === 'error') throw new Error(`the actor failed: ${messageOf(after.error)}`);
    },
    getState: () => select(current.getSnapshot()),
    subscribe(listener) {
      listeners.add(listener);
      return () => {
        listeners.delete(listener);
      };
    },
    persist: () => current.getPersistedSnapshot(),
    ...(restoreOptions ? { restore } : {}),
  });
  return Object.assign(target, { actor: () => current });
}

/**
 * Builds and starts the actor that will replace the live one (M5 design §3 step 2). Throws
 * `INVALID_SNAPSHOT` and leaves nothing running when construction or `start()` throws or the
 * started actor's status is `error`.
 */
function startReplacement<TLogic extends AnyStateMachine>(logic: TLogic, options: ActorOptions<TLogic>): Actor<TLogic> {
  let replacement: Actor<TLogic> | undefined;
  let failure: { error: unknown } | undefined;
  try {
    replacement = createActor(logic as AnyActorLogic, options as ActorOptions<AnyActorLogic>) as unknown as Actor<TLogic>;
    // Subscribed before start(), so a failed start reaches this observer rather than XState's
    // unhandled-error timer.
    const probe = replacement.subscribe({
      error: (error: unknown) => {
        failure = { error };
      },
    });
    replacement.start();
    probe.unsubscribe();
    const started = replacement.getSnapshot() as { status: string; error?: unknown };
    if (started.status === 'error') failure ??= { error: started.error };
  } catch (error) {
    failure = { error };
  }
  if (failure !== undefined || replacement === undefined) {
    replacement?.stop();
    const reason = `actor failed to start: ${messageOf(failure?.error)}`;
    throw new IronbirdError('INVALID_SNAPSHOT', `Invalid snapshot: ${reason}`, { path: '', reason });
  }
  return replacement;
}
```

````markdown
## Adapters

`@ironbird/redux` and `@ironbird/xstate` turn a state container into a core `Target`, so the daemon, the bridge, `@ironbird/testing`, and snapshots work with it unchanged. Both run in Node and Hermes and ship ESM and CommonJS builds with type declarations. Each lists `@ironbird/core`, `zod` ^4.2, and its library as peers. At runtime they import only `@ironbird/core`, plus `createActor` from `xstate`. Commands go through the registry first, so `toAction` and `toEvent` only ever see validated payloads.

### @ironbird/redux

```ts
function fromStore<R extends CommandRegistry, S, A extends Action = UnknownAction>(
  store: Store<S, A>,
  options: FromStoreOptions<R, S, A>,
): Target;

interface FromStoreOptions<R extends CommandRegistry, S, A extends Action = UnknownAction> {
  commands: R;
  toAction?: (command: CommandOf<R>) => A; // default: { type: name, payload }
  select?: (state: S) => unknown;          // default: the whole state
  restore?: { schema: z.ZodType<S> };      // requires withIronbirdRestore
}

function withIronbirdRestore<S, A extends Action, P = S>(reducer: Reducer<S, A, P>): Reducer<S, A, P>;
```

```ts
import { fromStore, withIronbirdRestore } from '@ironbird/redux';
import { configureStore } from '@reduxjs/toolkit';

export const store = configureStore({ reducer: withIronbirdRestore(rootReducer) });

// Command names match the slices' action types (`todos/add`), so the default toAction fits.
export const target = fromStore(store, { commands, select: (state) => state.todos, restore: { schema: rootStateSchema } });
```

- The default `toAction` produces the shape Redux Toolkit's action creators produce, so commands named after slice action types need no mapping.
- `select` shapes what `getState`, `waitFor`, and `watch` see. `persist` always returns the **root** state, `store.getState()`, because a projection can't rebuild the root reducer's state.
- The revision moves whenever the root state changes, including through dispatches made outside ironbird. A dispatch no reducer handles leaves it as it was.
- `restore` exists only with `restore: { schema }`, a Zod schema for the root state, and it requires the root reducer to be wrapped with `withIronbirdRestore`. The snapshot is parsed with `schema` first: a failure throws `INVALID_SNAPSHOT` with the first issue's `{ path, reason }` (a dot-separated path, `''` for the root) and leaves the store untouched. The adapter then dispatches one internal action, `@@ironbird/restore`, which the wrapper answers by returning the parsed value as the new state. If the store's state afterwards isn't that value, the reducer isn't wrapped, and the load fails `INVALID_SNAPSHOT` with `{ path: '', reason: 'the root reducer is not wrapped with withIronbirdRestore' }`.
- A command whose `toAction` returns the internal restore action fails `DISPATCH_FAILED`. Only a schema-checked snapshot may replace the state.
- Without `restore`, the target's capabilities are `['persist']`.

### @ironbird/xstate

```ts
function fromActor<R extends CommandRegistry, TLogic extends AnyStateMachine>(
  actor: Actor<TLogic>,
  options: FromActorOptions<R, TLogic>,
): ActorTarget<TLogic>;

interface FromActorOptions<R extends CommandRegistry, TLogic extends AnyStateMachine> {
  commands: R;
  toEvent?: (command: CommandOf<R>) => EventFromLogic<TLogic>; // default: { ...payload, type: name }
  select?: (snapshot: SnapshotFrom<TLogic>) => unknown;         // default: { value, context }
  restore?: {
    snapshotSchema: z.ZodType;
    actorOptions?: Omit<ActorOptions<TLogic>, 'snapshot' | 'state'>;
  };
}

type ActorTarget<TLogic extends AnyStateMachine> = Target & {
  /** The live actor; a restore replaces it. */
  actor(): Actor<TLogic>;
};
```

```ts
import { fromActor } from '@ironbird/xstate';
import { defineHeadless } from '@ironbird/core';
import { createActor } from 'xstate';
import { z } from 'zod';

export default defineHeadless(({ clock }) => {
  const actorOptions = { clock }; // delayed transitions run on the headless clock
  const target = fromActor(createActor(checkoutMachine, actorOptions).start(), {
    commands,
    restore: {
      snapshotSchema: z.looseObject({ status: z.literal('active'), value: z.string(), context: checkoutContextSchema }),
      actorOptions,
    },
  });
  return {
    target,
    dispose: () => {
      target.actor().stop();
    },
  };
});
```

- Pass a started **root** actor.
- The default event is the payload's keys plus `type: name`, with `type` applied last, so a payload key named `type` never renames the event. A payload that isn't an object is sent as `{ type: name, payload }`.
- The revision moves whenever the actor's snapshot changes, including through events sent outside ironbird and delayed transitions. An event no state handles leaves it as it was.
- `dispatch` fails `DISPATCH_FAILED` with `the actor is <status>` when the actor isn't active. It fails with `the actor failed: <message>` when the event puts the actor in error.
- The adapter observes the actor with an error callback, so an actor error never escapes through it as an uncaught exception. The error moves the revision, and the next dispatch reports it. XState rethrows an actor's error from a timer only when some observer lacks an error callback.
- `persist` returns `actor().getPersistedSnapshot()`. That value carries `undefined` properties, which `snapshotSave`'s strict serializer omits.
- `restore` exists only with `restore: { snapshotSchema, actorOptions? }`. It runs synchronously after validation, so no event reaches either actor in between:
  1. Parse the snapshot with `snapshotSchema`. On failure, it throws `INVALID_SNAPSHOT` with the first issue's `{ path, reason }`, and nothing has changed.
  2. Build and start the replacement: `createActor(actor().logic, { ...actorOptions, snapshot })`. If that throws or the actor's status is `error`, the replacement is stopped and the call throws `INVALID_SNAPSHOT` with `{ path: '', reason: 'actor failed to start: <message>' }`. The old actor stays live and subscribed.
  3. On success, the adapter moves its subscription to the replacement, makes `actor()` return it, stops the old actor, and notifies once.
- Write `snapshotSchema` with `z.looseObject`, or declare `children` and `historyValue`. `z.object` strips the keys it doesn't declare, and XState can't restore a snapshot without `children`; that fails at step 2.
- Pass the options the original actor was created with as `actorOptions`, especially `clock` in a headless definition. The replacement doesn't inherit them.

Consequences of a restore:
- App code holding the old actor reference sees a stopped actor. Read `actor()` instead, and read it again when the target notifies, for example to re-render. By the time the old actor's observers complete, `actor()` already returns the replacement.
- As in XState persistence, the restored state's invoked and spawned actors restart, and the old actor's stop. Entry actions aren't re-run. Both actors exist for one synchronous turn, so effects that start on `start()` can run once more than in the original timeline.
- Delayed transitions (`after`) that were pending when the snapshot was saved don't fire after a restore, because XState's persisted snapshot holds no scheduled events. A restored state waiting on a delay stays in it until an event moves it.
- `snapshotLoad` runs in the target's mutating queue, so no ironbird dispatch interleaves with a restore.
- Without `restore`, the target's capabilities are `['persist']`.
````

## Spec discrepancies and decisions

The spec, the contract, and the older docs agree except where noted. These points are decided here rather than silently:

| # | Spec, contract, or older doc says | This plan does | Why |
|---|---|---|---|
| 1 | Contract: `fromActor` returns `Target & { actor(): AnyActorRef }` | Returns `ActorTarget<TLogic> = Target & { actor(): Actor<TLogic> }` | `Actor<TLogic>` is assignable to `AnyActorRef` (verified by typecheck), so every contract consumer still works, and apps keep typed `send` and `getSnapshot` |
| 2 | Spec D2 says `fromActor(actor, ...)` with any actor; old api.md typed it `AnyActorRef` | Takes `Actor<TLogic>` with `TLogic extends AnyStateMachine` | Restore needs `actor.logic`, which only `Actor` has, and the default `{ value, context }` needs a machine snapshot |
| 3 | §3 step 3: "unsubscribe, subscribe to the replacement, stop the old actor, swap `current`, notify" | Swaps `current` **before** stopping the old actor | Stopping the old actor calls its observers' `complete`. App code there that reads `actor()` should get the replacement. A test pins this. Notify still happens once, last |
| 4 | Old api.md: default event `{ type: name, ...payload }` | `{ ...payload, type: name }`; a non-object payload becomes `{ type: name, payload }` | With the old order, a payload key named `type` would turn one command into another event. Spreading a string or number gives index keys or nothing (Review Focus 2) |
| 5 | Spec silent on revisions | Both adapters notify only when the root state or snapshot **reference** changes | Redux and XState both notify on no-op dispatches. Bumping then would make `watch` and `waitFor` wake for nothing, and modelTest's "rejected step changed state" check compares revisions |
| 6 | Spec silent on dispatching to a stopped, done, or errored actor, and on actor errors | `DISPATCH_FAILED` (`the actor is <status>`, `the actor failed: <message>`); the adapter's observer has an `error` callback | XState drops events to a stopped actor silently. Without an `error` callback on the adapter's observer, every actor error would become an uncaught exception from a timer, even in apps that handle errors (verified in XState's `_reportError`) |
| 7 | §3 and §12 name only invoked actors as a restore consequence | Also documents and tests that pending `after` transitions don't fire after a restore | Verified: XState's persisted snapshot holds no scheduled events. The spec's risk row ("documented and covered by a test") is extended to this case |
| 8 | Contract: peers "redux toolkit/redux" | Peer `redux` ^5.0.0 only; Redux Toolkit is a dev dependency | The adapter needs only Redux 5's types, and Redux Toolkit 2 depends on `redux` ^5.0.1, so Redux Toolkit users already have it. A Redux Toolkit peer would wrongly exclude plain Redux apps |

A `>=` range never forces Changesets to rewrite the dependents' versions. Plan 5 may raise the floor to `>=0.1.0` when it versions 0.1.0 |
| 10 | Peer floor for `xstate` unspecified | `^5.0.0` | Every API used (`Actor.logic`, `getPersistedSnapshot`, `ActorOptions.snapshot`) exists in the 5.0.0 declarations (verified). Tests run against 5.33 |
| 11 | D1 signature `fromStore(store, { commands, toAction?, select?, restore? })` | Adds a third type parameter `A extends Action = UnknownAction` | Apps that type their store with an action union (`Store<S, MyAction>`) otherwise fail to typecheck (verified) |
| 12 | D12: `INVALID_SNAPSHOT` details `{ path, reason }`, path format unstated | Dot-separated path from the first Zod issue, `''` for the root | That is the protocol's path convention (protocol.md §1 and the `UNSERIALIZABLE_STATE` warning), and §3 already uses `path: ''` for the root |
