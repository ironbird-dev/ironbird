# M4 Mutation Testing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run StrykerJS on `packages/core/src/clock.ts` and `packages/core/src/tracker.ts` through `pnpm mutation`, measure a baseline, add clock and tracker tests that kill the surviving mutants that represent real behavior until the mutation score is at least 70%, and record the score and the equivalent mutants in `docs/evals/m4-testing-package.md`.

**Architecture:** Two new root files and one new core file. `stryker.config.json` mutates only the two source files and runs core's own unit tests through a dedicated Vitest config, `packages/core/vitest.stryker.config.ts`, because the root `vitest.config.ts` has `test.projects` that include daemon and device tests. The Stryker Vitest runner is the default. Its current release (10.0.0) predates Vitest 5, so Task 1 checks it against Stryker's command runner (`vitest run -c packages/core/vitest.stryker.config.ts`, slower but independent of Vitest's internals) and keeps whichever runner gives correct results. Source files change only when a surviving mutant reveals a real bug: the fix then gets a failing test first, the minimal change, and a `@ironbird/core` changeset. Otherwise only `clock.test.ts` and `tracker.test.ts` grow, and every new test is first shown to fail against its mutant applied by hand. Nothing here runs in CI.

**Tech Stack:** StrykerJS 10.0.0 (`@stryker-mutator/core`, `@stryker-mutator/vitest-runner`; Node >= 22), Vitest 5.0.0 (lockfile), fast-check 4, TypeScript 6 strict, pnpm 12 workspaces. Node 22 in CI, Node 26 locally.

**Spec:** M4 design, `docs/superpowers/specs/2026-10-03-m4-testing-package-design.md`. During planning it lives at `docs/superpowers/specs/2026-10-03-m4-testing-package-design.md`, and it is committed on branch `m4-testing-package`. This plan covers §1 (criterion 2, "Mutation score ≥ 70% on the clock and tracker"), D8, §7, and the mutation rows of §8 to §10. This is plan 3 of 3 (spec §3). It is independent of plans 1 and 2. The cross-plan names are in `m4-contract.md`, "Plan 3: mutation".

**Prerequisites:** Branch `m4-testing-package`, stacked on `m3-agent-interface`, with `pnpm build && pnpm lint && pnpm typecheck && pnpm test` passing.

## Review Focus

These are the five failure modes most likely to give a wrong score or a broken workspace that no unit test catches. Each line names the task step that checks it.

1. **The Stryker Vitest runner misreads Vitest 5.** Expected: either it runs cleanly and agrees mutant by mutant with the command runner, or it is replaced. The silent case is wrong per-test coverage, which shows up as many `NoCoverage` mutants or obviously tested mutants marked `Survived`. Check: Task 1, Steps 7 to 9 (dry run, then a full run with both runners and a per-mutant comparison).
2. **Timing-sensitive tracker tests flake under mutation load.** Several tests wait 40 to 60 ms of wall-clock time. A flake kills a mutant that the tests can't actually catch, which inflates the score. Expected: the score is reproducible. Check: Task 4, Step 2 (two full runs whose per-mutant results must match).
3. **The Stryker sandbox misses pnpm's nested `node_modules`.** Core's tests import `zod` from `packages/core/node_modules`. Expected: the dry run passes, or the configured fallback is used. Check: Task 1, Step 7.
4. **A leftover `.stryker-tmp/` sandbox leaks into lint, tests, or git.** This happens after a crash or Ctrl-C. Expected: `git status` is clean after a run, and `pnpm lint` ignores a sandbox. Check: Task 1, Step 11.
5. **New fake-timer tests leak into other tests or hang.** Expected: every `describe` that fakes timers restores them, and `pnpm test` passes on Node 22 and 26 in about the same time as before. Check: Task 2, Step 6 and Task 3, Step 6.

## Reading a Stryker report

All tasks use these commands. Run them from the repository root.

**List survivors.** This prints the file, line, column, status, mutator, replacement, and the original source line:

```bash
node -e '
const r = require(process.argv[1]);
for (const [file, f] of Object.entries(r.files)) {
  const lines = f.source.split("\n");
  for (const m of f.mutants) {
    if (m.status !== "Survived" && m.status !== "NoCoverage") continue;
    const { line, column } = m.location.start;
    console.log(`${file}:${line}:${column} ${m.status} ${m.mutatorName} -> ${JSON.stringify(m.replacement)}\n    ${lines[line - 1].trim()}`);
  }
}' "$PWD/reports/mutation/mutation.json"
```

To list one file only, add `if (!file.endsWith("clock.ts")) continue;` as the first line of the outer loop.

**Score per file.** Stryker's score is (Killed + Timeout) / (Killed + Timeout + Survived + NoCoverage). `CompileError`, `RuntimeError`, and `Ignored` are not counted.

```bash
node -e '
const r = require(process.argv[1]);
const total = {};
const show = (name, c) => {
  const detected = (c.Killed ?? 0) + (c.Timeout ?? 0);
  const valid = detected + (c.Survived ?? 0) + (c.NoCoverage ?? 0);
  console.log(name, JSON.stringify(c), "score", (100 * detected / valid).toFixed(2));
};
for (const [file, f] of Object.entries(r.files)) {
  const c = {};
  for (const m of f.mutants) { c[m.status] = (c[m.status] ?? 0) + 1; total[m.status] = (total[m.status] ?? 0) + 1; }
  show(file, c);
}
show("total", total);' "$PWD/reports/mutation/mutation.json"
```

**Compare two reports mutant by mutant.** Mutant ids are unique only within one report, so a mutant is identified by file, position, mutator, and replacement. Killed and Timeout both count as `detected`.

```bash
node -e '
const load = (p) => {
  const out = new Map();
  for (const [file, f] of Object.entries(require(p).files))
    for (const m of f.mutants)
      out.set(`${file}:${m.location.start.line}:${m.location.start.column} ${m.mutatorName} ${JSON.stringify(m.replacement)}`,
        m.status === "Killed" || m.status === "Timeout" ? "detected" : m.status);
  return out;
};
const a = load(process.argv[1]), b = load(process.argv[2]);
let diff = 0;
for (const [k, s] of a) if (b.get(k) !== s) { diff++; console.log(k, s, "->", b.get(k)); }
for (const k of b.keys()) if (!a.has(k)) { diff++; console.log(k, "missing in first"); }
console.log(`compared ${a.size} mutants, ${diff} differ`);' "$PWD/<first>.json" "$PWD/<second>.json"
```

(`node -e` evaluates CommonJS even though the root `package.json` has `"type": "module"`, so `require` works. With `-e`, `process.argv[1]` is the first argument after the script.)

- **`plugins`** isn't set: the default, `@stryker-mutator/*`, finds the runner in the root `node_modules`. If Step 7 reports "Cannot find TestRunner plugin 'vitest'", add `"plugins": ["@stryker-mutator/vitest-runner"]` and note it in the report.

### Task 2: Kill the real surviving mutants in clock.ts

**Files:**
- Test: `packages/core/src/clock.test.ts`
  - Imports at line 2.
  - New manual-clock tests go inside `describe('createManualClock')`, after the last test (the "property: timers fire in non-decreasing due order" test that starts at line 124).
  - A new `describe` goes at the end of the file.
- Modify only for a real bug: `packages/core/src/clock.ts`, plus `.changeset/m4-core-<slug>.md` (see the bug-fix rule in Global Constraints)

**Interfaces:**
- Consumes:
  - From Task 1: `reports/mutation/baseline.json`, the survivor list, and `pnpm mutation`.
  - From `./clock`: `createManualClock`, `createRealClock`, `MAX_FIRINGS_PER_ADVANCE`.
  - From `./errors`: `isIronbirdError`.
- Produces: new tests in `clock.test.ts`, and for Task 4 a table of every clock.ts survivor with its outcome (killed by which test / equivalent / left alive) and the reason.

**Procedure.** Survivors aren't known until Task 1 runs, so work through them one at a time:

1. **List** the clock.ts survivors from `reports/mutation/baseline.json`. Use "List survivors" from "Reading a Stryker report" with the `clock.ts` filter.
2. **Classify** each one. Read the line in `clock.ts` with the replacement applied, then ask whether any call through the public API could observe a difference. The public API is `createManualClock`, `createRealClock`, `Clock`, `ManualClock`, `MAX_FIRINGS_PER_ADVANCE`, and `ScheduledTimer`, as documented in `docs/api.md`. Observable means a return value, a thrown error and its code, message, or details, the order or `now()` of callbacks, whether a callback runs at all, or whether a key is present in a `timers()` entry.
   - **Real:** some call observes it. Kill it.
   - **Equivalent:** no call can observe it. Write a one-line reason.
   - **Left alive:** it is observable only by wall-clock timing or by an input no caller can produce. Write a one-line reason. These still count against the score.
3. **Real survivors:** look the mutant up in the catalogue below. Its test kills the mutants listed for it.
